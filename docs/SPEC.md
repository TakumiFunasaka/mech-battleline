# ゲーム仕様 v0.3

## 1. 構成要素

### ユニットカード
- 社は6社あり、**毎試合そのうち5社をランダムに選んで使う**。5社 × 機種番号1〜9 ＝ 45枚（2026-10-19 に6社54枚から変更。BALANCE.md）。全カードが一意（各社が各番号を1枚ずつ持つ）。
- カード = (company, number)。社は色で区別。社ごとの性能差はない。
- 機体名などの表示データは `data/units.json`。

### 属性（番号に固定）

| 番号 | 機種 | 属性 |
|---|---|---|
| 1 | 偵察ドローン | 飛行 |
| 2 | 軽装スカウト | 地上 |
| 3 | 工兵機 | 履帯 |
| 4 | 装甲輸送機 | 履帯 |
| 5 | 主力汎用機 | 地上 |
| 6 | 空戦機 | 飛行 |
| 7 | 砲撃支援機 | 地上 |
| 8 | 重装甲機 | 地上 |
| 9 | 移動要塞 | 地上 |

### 戦場
- 5つを横一列に並べる（2026-10-19 に7から変更。第9節・BALANCE.md）。
- 地形は「平原」が基本。特殊地形は次の2種。

| 地形 | 有利属性 |
|---|---|
| 平原 | なし |
| 空域 | 飛行 |
| 悪路 | 履帯 |

## 2. 準備

1. 5戦場のうち、ランダムな1〜2か所を特殊地形にする（個数は1か2をランダム、種類は空域・悪路からランダム、同種の重複可）。残りは平原。地形は開始時から両者に公開。
2. 6社から5社をランダムに選び、その45枚をシャッフルして、各プレイヤーに6枚配る。残りが山札。使う5社は両者に公開。
3. 先手をランダムに決める。

## 3. 手番

1. **配備**：手札から1枚を選び、未決着の戦場の自分側に置く。各戦場の自分側は最大3枚。地形による配置禁止はない。
2. **決着処理**：全戦場について第5節の判定を行う。
3. **勝利判定**：第6節。
4. **補充**：山札があれば1枚引く。なければ引かない。

- 置ける場所がない（未決着戦場の自分側がすべて3枚）場合はパス。パスでは補充しない。
- 置ける場所がある限り、配備は義務（パス不可）。

## 4. 編成（3枚）の評価

強い順：

| 順位 | 役 | 条件 |
|---|---|---|
| 5 | 純正コンビネーション | 同じ社 かつ 連番 |
| 4 | 同型機編隊 | 3枚とも同じ番号 |
| 3 | 純正チーム | 同じ社 |
| 2 | 連携編成 | 連番（社は不問） |
| 1 | 寄せ集め | 上記以外 |

- 連番は昇順に並べて差が1ずつ。9→1の循環はない。
- **特殊地形での格上げ**：有利属性のカードを**2枚以上**含む編成は、役の順位が1段上がる（純正コンビは最上位のさらに上）。下の比較の「役の順位」は格上げ後の順位を使う。平原では起きない。
  - 空域（1・6）では連番に1と6が同時に入らないので、格上げされるのは同型機（1-1-1／6-6-6）・純正チーム・寄せ集めだけ。悪路（3・4）では連番（2-3-4／3-4-5）も格上げされる。
- 比較の順序：
  1. 役の順位が高い方が勝つ
  2. 同順位なら、**その戦場が特殊地形の場合**、有利属性のカードを1枚以上含む側が勝つ（両方含む／両方含まない場合は次へ）
  3. 番号の合計が大きい方が勝つ
  4. それも同じなら、先に3枚目を置いた側が勝つ

## 5. 戦場の決着

- 両者が3枚ずつ置いた戦場：第4節で比較し、勝者が確保。
- 片側だけ3枚そろっても決着しない（本家の「証明による確保」は採用しない。第9節）。
- 決着するのは両者が3枚ずつそろった戦場だけなので、空き枠が消えることはなく、両者とも勝敗がつくまで毎手置ける（パスは実際には起きない）。
- 確保済みの戦場には以後配置できない。
- 決着処理は各手番の配備直後に、自動で全戦場について行う（アプリでは宣言不要）。

## 6. 勝利条件

次を先に満たした側が即勝利：
- 3つの戦場を確保（5戦場の過半数）
- 隣接する3つの戦場を連続で確保（5戦場では過半数に含まれるので、実質的に「3つ確保」だけになる）

両者とも置けず山札も尽きたら、確保数の多い側の勝利。同数なら引き分け。

## 7. CPU（MVP用ヒューリスティック）

参考実装：`reference/sim/sim3.py` の `play()` 内と `sim5.py`（地形込み）。

- 候補手 = (手札の各カード × 置ける各戦場)。
- 各戦場について「楽観的上限」= 盤面に出ていないカードを自由に使えるとして到達可能な最良の編成値を計算する（`pot()` 関数）。
- スコア = (置いた後の自分の上限 − 相手の上限) + 0.6 × (置いた後の自分の上限 − 置く前の自分の上限)
- 相手が完成済みで、自分の上限が相手の値以下（負け確定）の戦場は、番号の低いカードの捨て場として扱う（スコア = −1000 − 番号）。
- 同点はランダム。
- 既知の癖：純正コンビネーションを狙いすぎる。難易度調整は後回しでよい。

## 8. テストケース（最低限）

- 赤7・赤8・赤9（純正コンビ）> 青5・赤5・黒5（同型機）
- 青5・赤5・黒5（同型機）> 青2・青6・青9（純正チーム）
- 青2・青6・青9（純正チーム）> 黄3・赤4・白5（連携）
- 黄3・赤4・白5（連携）> 赤9・青9・黄8（寄せ集め、合計26）
- 赤8・青9・黄1 は連番ではない（寄せ集め）
- 空域で、赤2・青2・黄2 vs 赤6・青6・黄6 → 6の方が勝つ（両方同型機、6は飛行）
- 空域でも、青7・青8・青9（純正コンビ）> 赤1・赤3・赤5（純正チーム、飛行含む）：役の順位が優先
- 空域で、赤1・赤2・赤4（純正チーム、飛行含む、合計7）> 青2・青5・青8（純正チーム、飛行なし、合計15）
- 平原で同役・同合計なら、先に3枚目を置いた側が勝つ
- 片側だけ完成（赤7・赤8・赤9 vs 空）では決着せず、相手はその戦場に置ける
- 悪路で、赤3・赤4・赤9（純正チーム、履帯2枚で格上げ）> 青8・黄8・白8（同型機、履帯なし）。赤3・赤7・赤9（履帯1枚）なら負ける
- 悪路で、赤2・赤3・赤4（純正コンビ、履帯2枚）> 青7・青8・青9
- 空域で、赤6・青6・黄6（同型機、飛行3枚で格上げ）> 白7・白8・白9（純正コンビ、飛行なし）
- 5戦場で3つ確保での勝利（7戦場の設定で、隣接3つ・4つ確保での勝利も確認）、山札切れ後の終了処理

## 9. 不採用（実装しない）

- 指揮官（戦術）カード
- 戦場の段階的拡大（後手有利の偏りが出た）
- 地形による配置禁止・機能停止（効果が禁止と同じで、上位の役を削るだけになった）
- 7戦場（2026-10-19 に5戦場へ変更）：証明による確保をやめた7戦場では、CPU同士で後手有利（先手勝率 約45%）。社数・番号の範囲・手札枚数・地形の数を変えてもほぼ動かず、5戦場で 約48%（手札5なら 約50%）になった。詳細は BALANCE.md。
- 地形の効果の別案（2026-10-19 不採用）：有利属性1枚で役が上がる（両者とも入れるので相殺され、強くするほど入場料になる）、有利機を社のワイルドにする（特殊地形が純正コンビの取り合いになる）。
- 証明による確保（2026-10-18 不採用）：片側だけ完成した戦場を「相手がもう上回れない」と示して確保するルール。確保で相手側の空き枠が消え、置けなくなった側がパスし続けられる一方、相手は完成済みの編成へ置かされ続けるため、置けなくなった側が有利になった（CPU同士400戦で、片方が置けなくなる試合が12%、その側の勝率63%）。実装は設定 `proofSecuring` で切り替え可能なまま残している。外した場合の比較：平均手数 35.9→39.8、先手勝率 52.0→49.0%、最初に戦場を確保した側が負ける試合 36→20%。

## 10. 未決事項

- 特殊地形の個数：1か2のランダム（各固定値では検証済み、ランダムは未検証）
- 社名・機体名は仮称
- オンライン対戦の要否
- 【確認メモ】証明による確保をやめたので、1手で決着するのはその手で置いた戦場1つだけになり、両者が同時に勝利条件を満たすことはない（証明ありに戻す場合は、手番のプレイヤーの勝ちとする実装が入っている）。
- 【確認メモ】第3節のパスと第6節の「両者とも置けず山札も尽きたら」は実際には起きない。全枠が埋まれば全戦場が決着し、戦場数が奇数なので必ずどちらかが過半数を確保する。実装では保険として残している。
- 社数：5戦場（30枠）に54枚だと終局時に山札が約14枚残り、ほしい札が最後まで出ないことが多かった。5社45枚で残り約5枚、先手勝率は 約49%。
- 手札枚数：5戦場では手札5のほうが先手勝率が50%に近い（6枚で 約48%、5枚で 約50%）。人間のテストプレイで決める。
- 5戦場で隣接勝利がなくなったことで、戦場の並び順の駆け引きが失われていないか（人間のテストプレイで確認）。
- 【実験・設定でオフ】社の設定をルールに乗せる案（2026-10-19）。いずれも共有山札では「両者が同じ札を使い、引けるかは運」なので、陣営としての差にならなかった。デッキ制（`docs/SPEC_DECK.md`）の試作に移った。
  - 契約企業（`contracts`）：各自に1社をランダムに割り当て、その社の機体を置いたときだけ効果。契約社ごとの勝率は 47〜52% で、効果がほぼ試合に現れなかった（契約社の札は1試合に平均4枚程度しか手に入らない）。
  - 社ごとの番号構成（`companyNumbers`）：社ごとに持つ番号を変える。社の勝ちへの貢献度を 38〜43% にそろえ、空域では飛行機の多い社、悪路では履帯の多い社が活躍する形にできたが、プレイヤーの判断はほぼ変わらなかった。
- 人間のテストプレイで確認したいこと：証明なしで、序盤のリードがそのまま勝ちにつながりやすくなっていないか（CPU同士では「最初に確保した側が負ける」試合が36%→20%に減った）。
